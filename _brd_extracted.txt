2. Overview & Purpose
The Admin login in Tx-Catalyst provides elevated access to the primary administrator — Adeesh Jain — and any designated admin-level users. While a standard User logs opportunities and a Reviewer evaluates them within their practice area, the Admin has complete cross-portal visibility and control.
The Admin login is responsible for:
Overseeing all leads across all practice areas and all users
Managing user accounts — creating, editing, and deactivating users
Configuring reviewer-to-practice routing rules
Mapping stakeholders to accounts and leads
Manually resolving leads that fail auto-routing (Exception Queue)
Monitoring the leaderboard and reviewing performance across the team
Receiving a CC notification on every lead submitted portal-wide
Note: The Admin module is a superset of both the User and Reviewer modules. The Admin can perform all actions available to Users and Reviewers in addition to the administrative capabilities described in this document.

6. Submit New Lead
The Admin can submit a lead directly using the same form available to standard Users. All mandatory and optional fields, routing logic, notification triggers, and points awards are identical to those defined in the User Login BRD (Section 5.3).
Additional Admin-specific behaviour:
The Admin can submit a lead on behalf of another user by selecting a 'Submit on behalf of' field (user dropdown) — the points for the submission are credited to the selected user, not the Admin
If the Admin submits without selecting a proxy user, the lead is attributed to the Admin account
Routing logic remains the same — practice area determines the assigned reviewer

13.3 Edit / Deactivate a Routing Rule
Admin can update the Assigned Reviewer for any existing rule — e.g., when a Delivery Head changes
Deactivating a rule causes future leads matching that rule to fall into the Exception Queue
All changes to Routing Config are logged in the audit trail
13.4 Rule Conflict Resolution
If two active rules match the same lead, the rule with the higher Priority number takes precedence
If priority is equal, the more specific rule (Existing Client over All) takes precedence
If no rule matches, the lead enters the Exception Queue automatically

16. Acceptance Criteria
The following criteria must be met before the Admin module is considered production-ready:
#
Feature
Acceptance Criteria
AC-A01
Admin Dashboard
Admin dashboard shows portal-wide KPIs (not scoped to logged-in admin's own leads). All counts are accurate and real-time.
AC-A02
Add User
Admin can create a new user with all mandatory fields. User receives a welcome email. New user can log in with the set credentials.
AC-A03
Edit User
Admin can update user name, email, role, and practice area. Changes reflect immediately across the portal.
AC-A04
Deactivate User
Deactivated user cannot log in. Their historical data and points are preserved. Leads previously assigned to a deactivated reviewer appear in the Exception Queue.
AC-A05
Submit on Behalf
Admin can submit a lead on behalf of another user. Points are credited to the selected user, not the Admin.
AC-A06
My Assignments
New client leads route to Admin's My Assignments. Admin can approve, reject, or re-assign. Status changes trigger correct notifications and points.
AC-A07
Exception Queue Entry
Any lead that fails auto-routing must appear in the Exception Queue within 60 seconds of submission.
AC-A08
Exception Queue Resolution
Admin can assign an exception lead to a reviewer. Lead exits queue, reviewer is notified, user is notified.
AC-A09
Routing Config — Add
Admin can add a new routing rule. Subsequent leads matching the new rule are routed correctly.
AC-A10
Routing Config — Deactivate
Deactivating a routing rule causes new matching leads to fall into Exception Queue, not silently fail.
AC-A11
Stakeholder Mapping
Adding a stakeholder with Notification Opt-in ON results in that stakeholder receiving notifications for leads on that client.
AC-A12
Reviews — Override
Admin can override a lead's status. Points are credited per the milestone. Override is logged in the Audit Log with reason.
AC-A13
Leaderboard Filters
Admin can filter leaderboard by practice area and date range. Exported CSV matches the filtered view.
AC-A14
Points Config
Admin can change milestone points values. New values apply only to future milestones. Existing points are unchanged.
AC-A15
Audit Log
Every admin action (override, deactivation, routing change, config update) appears in the Audit Log with actor, timestamp, and detail.
AC-A16
Admin CC Notifications
Admin receives a portal and email notification for every single lead submitted across the portal, regardless of practice area or user.
AC-A17
Role-Based Access
Admin login provides full portal visibility. A Reviewer attempting to access Admin-only sections receives an access denied error.
17. Non-Functional Requirements (Admin Module)
Category
Requirement
Security
Admin credentials must be stored with bcrypt hashing. Admin sessions expire after 60 minutes of inactivity.
Access Control
RBAC enforced — Admin-only pages return HTTP 403 Forbidden for Reviewer or User session tokens.
Performance
Reviews and Exception Queue pages load within 3 seconds even with 1,000+ leads in the system.
Audit Integrity
Audit Log entries are immutable — no user (including Admin) can edit or delete log entries.
Data Export
Leaderboard and Reviews export must complete within 10 seconds for datasets up to 10,000 rows.
Email Delivery
All notification emails must be delivered within 5 minutes of the triggering event.
Availability
Admin module must be available 99.5% of business hours; planned maintenance windows communicated 24 hours in advance.
18. Assumptions & Constraints
18.1 Assumptions
Adeesh Jain is the primary Admin for Phase 1. Additional admins can be created by the existing Admin via the Accounts section.
Practice areas are fixed for Phase 1 (QE, Data Engineering, Digital Engineering & AI, Insurance). New areas can be added via Admin Settings but require a routing rule to be created before leads can be routed.
All reviewer account changes (deactivation, practice re-assignment) are communicated to the Admin prior to implementation to allow proactive routing updates.
The portal is an internal tool; authentication is form-based login (no SSO in Phase 1 unless separately scoped).
The Audit Log is read-only and cannot be exported in Phase 1 — it is viewable on-screen only.
18.2 Constraints
CRM integration is out of scope for Phase 1 — Sales handoff remains manual.
The Admin cannot delete leads or user point histories — only deactivate accounts and override statuses.
Bulk actions (bulk approve, bulk reassign) are out of scope for Phase 1.
Email notification template customisation is out of scope for Phase 1.
